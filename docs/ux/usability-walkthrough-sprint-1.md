# Persona-Based Usability Walkthrough – Sprint 1

This exploratory walkthrough used four fictional user profiles between 17 and 55 years old to inspect the planned Sprint 1 flow. It was not a test with real participants and does not provide empirical usability evidence.

Login → Find match/stadium → Check-in → Confirmation → Visit History

The simulation focuses on US01, US02, US03, US04 and US06, which form the core Sprint 1 user flow.

## Potential UX risks identified

The walkthrough did not reveal an obvious logical blocker in the proposed flow, but because no real users participated, task completion cannot be claimed. The following potential risks were identified:

- A simulated persona could hesitate between match and stadium information before starting the check-in.
- A user may expect automatic redirection to Visit History after completing the check-in.
- Visit History may take extra time to locate.
- The Check-in button may be overlooked if it is not visually prominent.
## Experience Lead findings

The walkthrough suggests three areas that should receive particular attention during implementation and later real-user testing:

1. Check-in visibility
The primary Check-in action should be visually prominent on the match/stadium page.

2. Confirmation and next action
After a successful check-in, the user should receive clear confirmation and an obvious option to view the saved visit.

3. Visit History discoverability
Visit History should be clearly accessible through the main navigation.

## Recommended actions
Keep Check-in as the primary action on the match/stadium screen.
Provide a clear success message after check-in.
Include a "View my visits" action on the confirmation screen.
Keep Visits visible in the main navigation.
Validate these observations with real users once the Sprint 1 implementation is testable.
## Conclusion

The planned Sprint 1 flow is internally coherent, but the walkthrough cannot establish that real users will complete it successfully. The observations above are hypotheses for the Experience Lead to validate during implementation and future real-user usability testing.
